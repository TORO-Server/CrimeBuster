# 通報の仕様

通報先は、Discord のフォーラム (チャンネル ID は環境変数 `REPORT_CHANNEL_ID` で指定) である。

## 投稿の形式

- 投稿の名前は、荒らしの名前。本文に、ワールド、名前と UUID、座標、範囲、時間、数、主な破壊、使ったコマンド、対応を書く
- 画像: 被害の全体 → (範囲が広いときは) いちばん壊された所に寄った画面 → (ロールバックできたら) 復旧後。Renderer で撮れなかったときは、真上から見た図で埋める
- Renderer は「いまの地形」だけを描くので、穴や欠けだけでは、どこが荒らされたか分からない。そこで、撮った画面の上に印を重ねる: 壊された列を赤い縦線、主な範囲 (壊した数の 97%) を黄色の枠、左上に名前と壊した数。印は、Renderer が返したカメラの変換を使ってこちらで描く。復旧後の画面は、同じカメラで、赤い線なしで撮る (前後を比べられる)。印の文字は ASCII だけ (実行する環境に日本語のフォントが無いため)
- ロールバックできたら、タグ (`ROLLBACK_TAG_ID`) を付ける
- 同じ人は 24 時間以内なら、新しく立てず、同じ投稿に書き足す
- embed は使わず、普通の文字だけで書く (フォーラム側の権限の都合)
- 誤検知のときに戻せるよう、報告に復旧のコマンド (`co restore ...`) を書く
- 投稿は `allowed_mentions` を空にして、だれにも通知しない
- プレイヤーの書いた文字 (発言・コマンド・名前) と、確認した人のメモは、制御文字を除いて 1 行にし、`@` とインラインコードの区切りとマスクリンクを無効にしてから載せる

## 撮影

TORO-Renderer の描画 API (`RENDERER_URL`) に、荒らされた場所の中心 (壊した数の重み付きの中央値) へ向けたカメラで描かせる。Renderer は region ファイルを直接読むので、地図の更新を待つ必要はない。

- 撮る前に `save-all flush` を送り、メモリ上の変更を region ファイルへ書き出す。書き出しは 1 分に 1 回まで (プレイヤーの行動だけでサーバーの負荷が増えないようにする)
- 看板の文字列は描かない (ブロックの形は写る)。プレイヤーの指定した画像や動画を読む仕組みは、撮影の経路に無い
- 1 枚の描画は数秒のオーダー
- 撮れなかったときは、画像なし (または真上の図だけ) で続ける。ロールバックも通報も止めない

## Discord の認証

ボットのトークンは、DiscordSRV の設定 (`DISCORDSRV_CONFIG`) の BotToken を、読み取り専用でマウントして読む。トークンを環境変数のファイルやリポジトリに写さない。専用のボットを作るときは、`DISCORD_BOT_TOKEN` (または `DISCORD_BOT_TOKEN_FILE`) で渡す。これがあれば DiscordSRV の設定は読まない。

REST だけを使い、Gateway には接続しない。

## MCP 経由で投稿する

Discord への投稿は、Discord-MCP サーバーの MCP 経由で行う。crime-buster は MCP のクライアントで、ステートレスな Streamable HTTP (`DISCORD_MCP_URL`) に `tools/call` を 1 回ずつ送る。

- サーバーにはトークンを置かない。crime-buster が DiscordSRV の BotToken を、呼ぶたびに `authOverride` で渡す。サーバー側で、トークンの上書きを許可する設定が要る
- 画像は Base64 で渡す (サーバーとディスクを共有しない)
- 使うツール: 自分のユーザーとチャンネルの確認、投稿を立てる、書き足す、タグを付けるためのもの

## AI の確認

`AI_API_KEY` (または `ANTHROPIC_API_KEY`) を渡すと、AI (Messages API、`AI_MODEL`) が 2 つの役をする。キーが無ければ使わない。

1. **荒らしの確認 (ロールバックの前)**: 集計 (数・範囲・主な破壊・コマンド・コンテナ) と画面 (赤い線つき) を見て、「荒らし」/「正当な作業」/「判断できない」と、確からしさ (0〜100) と一言を答える。「荒らし」で、`AI_MIN_CONFIDENCE` (既定 70) 以上のときだけロールバックする。そうでないときは、ロールバックせず、通報だけして「運営が確認してください」と書く。AI が使えない (エラー) ときは、既定では閾値の決まりだけで進める。`AI_REQUIRED=true` なら、AI が「荒らし」と言うまでロールバックしない
2. **チャットの監視**: 新しい発言を (最大 40 件を、1 人ずつ分けて) 見せて、暴言・性的な発言・差別・勧誘・スパムを選ぶ。回数の決まりでは見つからない発言を通報にする。`AI_CHAT=false` で止められる

安全の考え方: プレイヤーの名前・発言・コマンドは、AI には「データ」として渡し、命令には従わないように指示する。AI の答えが影響するのは「ロールバックを止める」と「通報する」方向だけで、AI の答えだけでロールバックやミュートが増えることは無い (ロールバックは、閾値を超えた事件にだけ行う。AI の判定だけで開いた事件は、`live` でもミュートせず通報だけにする)。発言は 1 人ずつ尋ねるので、ほかの人の発言の文字が、その人の判定に影響しない。AI の答えの文章は、改行を除き、`@` を無効にして、長さを切ってから報告に載せる。AI の判定の分類は、決めた言葉だけにする。

送信されるもの: 事件の集計と画面 (Renderer の画像)、チャットの発言 (名前つき) が、AI の API に送られる。
