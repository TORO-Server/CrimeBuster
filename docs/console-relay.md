# コンソール中継のプロトコル

Minecraft サーバーのコンソールへコマンドを送るために、Docker Engine の API (unix ソケット) で `docker attach` と同じように標準入力へ 1 行送り、出力を読む方式を使う。

ソケットは root と同じ力なので、crime-buster には持たせない。**同じイメージの `crime-buster console-relay` を別のコンテナで動かし、ソケットはそこだけにマウントする** (中継)。crime-buster と中継は、2 つだけの internal ネットワークでつなぐ (接続先は `CONSOLE_URL`)。

## 経路

```
POST /run {"cmd": "...", "timeout_ms": 1000}   200 のあと、コンソールの行を流す (timeout か、呼ぶ側が切るまで)
GET  /healthz                                  204
```

- つなぐのは、中継の設定で指定した 1 つのコンテナ (`MC_CONTAINER`) だけ。Docker の API は attach しか使わない
- 上限: 本文 4 KiB、同時に 4 本 (超えると 429)、`timeout_ms` は 1〜600000

## 送れるコマンド

送れるのは、文字列全体が次の形に一致するコマンドだけ。ほかは 403。名前はコネクタと同じ検証を通した形、ワールドと地図は `[A-Za-z0-9_-]{1,64}`。

- `save-all flush`
- `bluemap`
- `bluemap update <地図> <x> <z> <半径>` (半径は 1〜256)
- `co rollback u:<名前> t:<秒>s r:#<ワールド>` (秒は 87000 まで)
- `kick <名前> <理由>` (理由は制御文字を含まない 100 字まで)
- 中継の設定 `CHAT_MUTE_CMD` の `{name}` を正しい名前にしたもの

## 応答と完了の判定

- 200 は「コマンドを送った」という意味。attach が途中で切れると、終わりの印を付けずに接続を切る。呼ぶ側は、印の無い切断をエラーとして区別できる
- コンソールの行にはプレイヤーの発言も混ざる。完了の判定は、行の頭 (時刻とレベル) の直後の文言だけで見るので、発言と取り違えない。CoreProtect の完了の行は、対象の名前も照合する
- **ロールバックが効いたかは、データベースで確かめる** (`rolled_back` が 95% 以上)。コンソールが「完了」でもデータベースで戻っていなければ失敗、切断でもデータベースで戻っていれば成功として記録する。データベースを読めないときだけ、コンソールの完了の行を信じる
- コンソールの行は、コネクタの HTTP API の応答にも、事件の記録にも載せない (発言や、ログの設定によっては接続元のアドレスが混ざるため)

## 中継の動かし方

- 中継は `read_only`、`cap_drop: ALL`、`no-new-privileges`、非 root で動かす
- イメージにシェルが無いので、ヘルスチェックは `crime-buster healthcheck -relay`
- 中継の設定 (待ち受け、ソケット、コンテナ、ミュートのコマンドの形) は [configuration.md](configuration.md) の「コンソール中継」の表にある
