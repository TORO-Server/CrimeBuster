# 調査記録: エージェント (Muse) の仕様 (2026-11-04)

これは、2026-11-04 時点の調査の記録である。エージェント側の担当者に聞いた答えと、各社の資料による。その後の仕様変更は反映していない。規範ではない。ツール名は当時のものである。

| 項目 | 当時の内容 |
| --- | --- |
| コネクターの作り方 | 設定画面に URL 欄は無い。チャットで頼むと、エージェントがカスタムコネクターを作る (登録名は `custom.<名前>`、通信してよいホストは `api_hosts` に書いたものだけ、認証は `api_key` を Bearer ヘッダーに載せる形)。トークンは、安全な入力ページで人が入れる (チャットには貼らない)。方式と配置は、あとから変えられない |
| 呼び出し | モデルのツールにはならず、エージェントが CLI 越しに呼ぶ。1 回 45 秒で切れる、自動のやり直しは無い、HTTPS の 443、URL にクエリを付けられない。MCP の版は 2025-11-25 / 2025-06-18 / 2025-03-26 |
| ツールの許可 | `list-tools` で見えたうち、`ALLOWED_TOOLS` に入れたものだけを呼べる。あとから増えたツールは、見直して足すまで使えない |
| 定期タスク | cron のタスクが、バックグラウンドで、コネクターのツールを呼べる。結果は、タスクを作ったチャットに届く。失敗やタイムアウトは、チャットに届かず、実行履歴にだけ残ることがある。間隔は `5m` `1h` など。最短の保証は無く、前後数分ずれる |
| 人の確認 | コネクターごとに、読み取りと書き込みを別々に Allow / Ask / Deny にできる。状態を変える操作は、ユーザーの許可が要る扱い。定期タスクの途中で承認が要ると、その実行は承認待ちで止まる |
| 画像 | 標準の CLI は、MCP の image コンテンツ (base64) を、ただの文字として出すだけで、画像として見ない。見るには、base64 をファイルに保存して開くヘルパーが要る |

この調査から、当時の設計は次のようにした。

- 撮影 (1 分ほど) は、始める呼び出しと取る呼び出しの 2 回に分けた。ロールバックも裏で動く。どの呼び出しも 45 秒より短く返る
- 事件の画像は、事件ができたときに作ってあるので、画像を取る呼び出しはすぐ返る
- 書き込みのツールと読み取りのツールを、名前で分けた。エージェント側の Ask / Allow を、そのまま使える
