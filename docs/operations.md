# 運用

## 導入手順

1. イメージを用意する。タグ `v*` か main への push で、CI がイメージを作る。またはローカルで Dockerfile からビルドする
2. `compose.example.yaml` のサービス (本体、Discord-MCP) とネットワークを、自分の docker-compose.yaml に足す。データ用のディレクトリ (非 root のユーザーが書けるもの) と、データベースのパスワードの secret を用意する。コンソールを使う場合は、Minecraft のサーバー側で RCON を有効にし (server.properties の `enable-rcon` と、ホスト側で管理するパスワード)、本体から RCON のポートへ届く経路を用意する
3. `CRIMEBUSTER_MODE=observe` で起動する。`crime-buster check -console` で、データベース・Discord・コンソールへの接続を確かめる (何も投稿しない)
4. 数日見て、検知の記録に誤検知が無いか確かめる
5. `dry-run` にして、データ用フォルダの `reports/` の画像と `report.md` を確かめる
6. `review` にし、連携する MCP サーバーにコネクタの接続先を渡して、コネクタ経由の操作 ([connector-api.md](connector-api.md)) を人が見て決める運用で数件通す
7. 自動でロールバックまでしたければ `live` にする (キックを使うかも、ここで決める)

設定値は [configuration.md](configuration.md) を見る。通報先のチャンネル ID やロールの ID など、既定値の無い項目は、使うモードでは必須である (起動時の検証で報告される)。

## データの保持

- 事件のフォルダ (`DATA_DIR/reports/<id>`) は `REPORT_RETENTION` (既定 90 日) で消す。起動したときと 1 時間ごとに見て、`0` なら消さない。動いている事件と、`reports/` と `shots/` の外には触らない。`audit.jsonl` は消さない
- コネクタ経由の撮影の結果 (`shots/`) は 2 時間で消す
- 1 件の事件の処理の全体の期限は 30 分

## ヘルスチェック

- `crime-buster healthcheck` は、監視の 1 回が最後に成功した時刻で判定する (2 分より古ければ失敗)。データベースにつなげないあいだは unhealthy になる

## 限界

- ロールバックは、その人の変更を、ワールド全体で戻す。他の人が、荒らされた場所に置いた物も、その人の変更の上に重なっていると、CoreProtect の決まりで巻き込まれることがある。古い事件ほど巻き込むので、コネクタ経由と自動のロールバックは、事件の始まりから 24 時間までにしている
- 道具 (WorldEdit など) を使う荒らしは、`review` 以外では対象外の決まりで見逃す (記録されたコマンドの文字列だけで決めるので、権限が無い人が打っただけでも対象外になる)。コマンドの記録が付くので、人が見られる。`review` では対象外にせず、事件に書く
- CoreProtect が記録しないもの (モブの大量発生、パケットの攻撃など) は見られない
- Renderer は region ファイルを読むので、撮影はディスクへ書き出された状態で撮る。書き出し (`save-all flush`) の直後に撮るため、通常は最新の状態になる
